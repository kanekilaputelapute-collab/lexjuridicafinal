# Leçons apprises

[28/03/2026] | Erreurs de type bloquant le build (comparaison impossible après narrowing) | Règle : TypeScript peut interdire une comparaison si un bloc IF/RETURN précédent garantit que la valeur est impossible. Supprimer les vérifications redondantes après un narrowing.
[28/03/2026] | Gemini a renommé LexJuridica en LexGemini dans 3 fichiers sans que ce soit demandé | Règle : ne jamais modifier branding/textes UI sans instruction explicite de l'utilisateur
[28/03/2026] | Des erreurs de type bloquaient le build (await manquant, null-safety) | Règle : Toujours lancer 'npm run build' après des modifications structurelles pour garantir l'intégrité du projet.
[29/03/2026] | L'énergie de départ (10/40) était hardcodée dans un script SQL (supabase_signup_fix.txt) et dans la UI | Règle : Toujours chercher les valeurs par défaut dans les scripts d'initialisation DB en plus du code. Utiliser des constantes pour les valeurs max affichées.
[30/03/2026] | Route AI vulnérable à l'épuisement de quota et au CSRF | Règle : Toujours vérifier l'auth, l'énergie ET l'Origin au tout début des routes API Next.js.
[30/03/2026] | XSS possible via dangerouslySetInnerHTML sur du contenu IA | Règle : Toujours utiliser un sanitizer (même basique) avant d'injecter du HTML provenant d'une IA.
[30/03/2026] | Les quêtes ne s'incrémentaient plus à cause d'un mismatch de type ('flashcard' vs 'flashcards') | Règle : Centraliser les types d'événements de gamification pour garantir la cohérence entre l'émission (updateGamification) et la réception (quests logic).
[30/03/2026] | Leaderboard fuyait les emails partiels même avec masquage UI | Règle : Toujours transformer les données sensibles (masquage) AVANT de les mettre dans le state React pour éviter qu'elles ne soient visibles via React DevTools ou le réseau.
